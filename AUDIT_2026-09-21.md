## Task 1 — System Mapping & Inspection

Focus Forest is a **Manifest V3 Chromium extension** (Chrome/Brave/Edge/Opera/Vivaldi, `minimum_chrome_version` 111 after this audit) that turns browsing into a visible "garden": the user plants a *mission* (intention), ordinary navigation grows *branches*, and when a branch gets deep the extension offers a calm, non-blocking moment of choice. Everything is **local-first**: one `chrome.storage.local` key (`focusForestState`), zero network calls, zero remote code.

### Component inventory

| Layer | Files | Role |
|---|---|---|
| Manifest | `manifest.json` | MV3 config: SW module background, newtab override, popup, options page, Alt+F command, content scripts (now two: MAIN-world bridge + isolated companion), tight extension-page CSP, `<all_urls>` host permissions, deliberately empty `web_accessible_resources` |
| Background | `background/service-worker.js` (1,345 ln) | The brain: navigation graph tracking, mutation queue, message router with schema validation + sender trust boundary + rate limiting, badge, alarms-driven quota compaction, import/export, dashboard stats aggregation, context menus |
| Shared | `shared/state.js` (683 ln), `shared/error-tracing.js`, `shared/constants.js`, `shared/theme.js`, `shared/chromium-api.js` | Schema (v4) + normalization/sanitization of every persisted field, LIMITS caps, reward catalog + earn/cooldown logic, storage cache with own-write guard, quota check/compaction; error traces with root-cause heuristics; `browser.*`→`chrome.*` alias |
| Content | `content/content.js` (646 ln), `content/spa-bridge.js` (new) | Closed-shadow-DOM companion chip + choice card + "Forest Find" reward toast, drag/keyboard-move, growth rituals, link-click tracking, SPA detection (bridge + popstate/hashchange + title observer + poll), and now cross-context storage sync |

| Tooling | `scripts/*.mjs`, `test-*.mjs`, `.github/workflows/ci.yml` | Packaging (zip/PowerShell), design preview server, Playwright performance profiler with hard budgets; 12 test files (unit, contract/sentinel, stress, browser); CI runs everything + packages artifacts |

### Data flow

1. **Planting** — New Tab / popup / context menu / Alt+F → `START_MISSION` → `createSession()` → serialized `mutate()` queue → `normalizeState()` → `chrome.storage.local.set` → badge + `storage.onChanged` fan-out.
2. **Growing** — page events (content `LINK_CLICK`, `OBSERVE_PAGE`, `SPA_NAVIGATION`; SW `webNavigation.onCommitted/onHistoryStateUpdated`, `tabs.onUpdated/onActivated/onRemoved/onCreated`) → `trackLink()`/`observeTab()` build a parent/child node graph with confidence tiers (`direct`/`tab-inferred`/`external`), depth-derived states, pending-branch/redirect resolution for `target=_blank` and redirector URLs.
3. **Intervening** — `GET_ACTIVE_VIEW` gives the content script a compact view; at `choiceDepth` the choice card offers Keep exploring / Return / Compost / New mission → `GO_HOME`, `COMPOST`, `END_MISSION`, `DISMISS_INTERVENTION`, optionally earning catalog rewards (`earnReward` with cooldown + per-session caps).
4. **Reflecting** — dashboard reads `GET_SNAPSHOT`/`GET_DASHBOARD_STATS`, renders the SVG tree (golden-angle sunflower packing inside a hand-drawn silhouette), trail notes, compost, finds, charts; export/import round-trips the full state through validation.
5. **Hygiene** — 5-minute alarm → quota check → compaction; per-write normalization caps (12 sessions × 96 nodes × 72 events × 80 compost); forget-site/forget-garden surgical removal with depth recomputation.

## Task 2 — Goal & Intent Reverse-Engineering

Reading the code's choices — not just its comments — the author's vision is unusually coherent:

1. **An attention companion, not a blocker.** Nothing ever prevents navigation. Depth thresholds (`gentleDepth` desaturates, `choiceDepth` offers *equal* choices) exist to create a moment of metacognition: "This path is deep, not wrong."
2. **Radical local-first privacy as an architectural invariant.** No network I/O anywhere; `web_accessible_resources` kept empty (and test-enforced); closed shadow root; constructable stylesheets to survive hostile page CSPs; no `innerHTML` sinks (test-enforced); tracking params stripped; broad host permissions justified in SECURITY.md. The repository-integrity test even fails the build if any source file contains an `http(s)://` literal.
3. **Anti-dark-pattern rewards.** "Forest Finds" are opt-in, deterministic-by-tier, cooldown- and cap-bounded, copy-audited by test to never contain scores/durations/urgency, and explicitly framed as "notes, not points." The author is deliberately building the *opposite* of streak-gamification.
4. **A reflection artifact.** The garden/tree is a keepsake visualization of *how* one wandered (link vs. new-tab vs. SPA vs. unlinked, with honest confidence labels), not a productivity score.
5. **Cross-Chromium portability + store readiness.** New-tab placeholder handling for six Chromium flavors, `browser.*` alias, CHROMEWEBSTORE.md, CI packaging.
6. **Defensive-by-construction state.** Every persisted field passes schema sanitization on both write and read; a serialized mutation queue with retry; a message router with schema validation, sender-trust gating, and rate limiting; layered error tracing with root-cause heuristics.
7. **Regression paranoia.** Five prior audit documents, sentinel tests that grep source for previously-fixed bug patterns, Playwright performance budgets in CI.

The audit below holds the codebase to exactly that standard: several findings are places where the implementation quietly failed its own stated philosophy (a privacy-preserving tool that could destroy your data; a "calm" UI showing buttons that do nothing; an SPA story that tests validated in a world where production doesn't live).

### Issue 1 — CRITICAL: storage read failure wipes all user data

- **File & Line Area:** `shared/state.js` (loadState, ~L508–550; compactStateIfNeeded ~L470–480) + `background/service-worker.js` (runMutatorWithRetry ~L120–140)
- **Failure Mode:** `loadState()` catches *any* `chrome.storage.local.get` rejection and returns `emptyState()` — sensible for read-only UI, catastrophic for the write path. `runMutatorWithRetry()` ran every mutation on `loadState()`: on a transient read error (corruption hiccup, quota weirdness, platform flake) the mutator received a fabricated empty state and `saveState()` **persisted it over the user's real forest** — all sessions, compost, settings, and reward history silently destroyed. Reproduced: `sessions in storage after one mutation on the failed-read empty state: 0`.
- **Original Code Fragment:**
```js
// shared/state.js
export async function loadState() {
  if (stateCache !== null) return stateCache;
  try {
    const result = await chrome.storage.local.get(STORAGE_KEY);
    stateCache = normalizeState(result[STORAGE_KEY]);
    return stateCache;
  } catch {
    return emptyState();
  }
}

// background/service-worker.js — runMutatorWithRetry
const attempt = async () => {
  const state = await loadState();
  const result = await wrappedMutator(state);
  ...
```
- **Fixed Code Replacement:**
```js
// shared/state.js — read-only consumers keep the gentle fallback (contract
// pinned by test-state.mjs), now with an explicit warning in the docstring:
/**
 * Loads the persisted Focus Forest state from chrome.storage.local.
 * Returns a cached copy if available and not invalidated.
 * READ-ONLY consumers: on a storage read failure this resolves to a fresh
 * empty state so UIs degrade to "nothing planted" instead of throwing.
 * Never use this inside a mutation that will be written back — persisting the
 * empty fallback over a transient read error would wipe the user's forest.
 * Write paths must use loadStateForWrite() instead.
 * @returns {Promise<object>} Normalized state object.
 */
export async function loadState() {
  if (stateCache !== null) return stateCache;
  try {
    const result = await chrome.storage.local.get(STORAGE_KEY);
    stateCache = normalizeState(result[STORAGE_KEY]);
    return stateCache;
  } catch {
    return emptyState();
  }
}

/**
 * Strict loader for write paths (mutations, compaction).
 * Identical to loadState() on success — including the shared cache — but a
 * storage read failure propagates instead of resolving to emptyState(). A
 * mutation that ran against a fabricated empty state would persist that empty
 * state on the next save and silently destroy every stored garden; aborting
 * the mutation keeps durable data untouched until reads recover.
 * A missing key is NOT an error: a genuinely empty storage normalizes to the
 * empty state and may legitimately be written to (first run).
 * @returns {Promise<object>} Normalized state object.
 * @throws When chrome.storage.local.get rejects.
 */
export async function loadStateForWrite() {
  if (stateCache !== null) return stateCache;
  const result = await chrome.storage.local.get(STORAGE_KEY);
  stateCache = normalizeState(result[STORAGE_KEY]);
  return stateCache;
}

// shared/state.js — compactStateIfNeeded (write path) now uses the strict loader:
  // Work on a copy: loadStateForWrite() returns the shared cache, and
  // compaction must never mutate it before (or without) a successful durable
  // write. The strict loader also guarantees a transient read failure aborts
  // compaction (throwing to the caller) instead of compacting—and then
  // persisting—an empty fallback state over the user's real data.
  const state = structuredClone(await loadStateForWrite());

// background/service-worker.js — import gains loadStateForWrite, and:
async function runMutatorWithRetry(wrappedMutator) {
  const attempt = async () => {
    // Strict loader: if the storage READ fails, abort the mutation instead of
    // running it against an empty fallback state — persisting that fallback
    // would wipe every stored garden on a transient read error.
    const state = await loadStateForWrite();
    const result = await wrappedMutator(state);
    if (result === NO_CHANGE || result == null) return result === NO_CHANGE ? null : result;
    await saveState(state);
    updateBadge();
    return result;
  };
  try {
    return await attempt();
  } catch (error) {
    clearStateCache();
    const result = await attempt();   // single-shot recovery still applies
    logWarning(new Error('mutation recovered on retry'), { category: ERROR_CATEGORIES.STATE_MUTATION, originalError: error?.message, component: 'service-worker', function: 'mutate-retry' });
    return result;
  }
}
```
Failure now surfaces as `INTERNAL_ERROR` to the caller with durable data untouched; a truly transient failure still recovers via the existing single retry (both paths pinned by test A1).

### Issue 3 — HIGH: spurious `reload` event after every link navigation

- **File & Line Area:** `background/service-worker.js` `observeTab()` same-URL branch (~L520–533)
- **Failure Mode:** For an ordinary same-tab link click the pipeline is: content `LINK_CLICK` → `trackLink()` creates the node and records `navigation` → browser commits (`onCommitted` stores hint `link`) → `tabs.onUpdated(complete)` → `observeTab()` finds `current.url === url` and unconditionally stamped `addEvent(session, 'reload', …)`. Every link click therefore recorded *two* events, the second one a lie ("Reloaded the page you were already on") in the dashboard trail, and burned the 72-event cap at double rate — evicting genuine history sooner. Reproduced: trail was `["mission_started","origin_planted","navigation","reload"]`.
- **Original Code Fragment:**
```js
if (current && current.url === url) {
  if (navigationHint === 'back-forward' || navigationHint === 'manual') {
    current.navigationKind = navigationHint;
    current.confidence = 'low';
  }
  addEvent(session, navigationHint === 'back-forward' ? 'back_forward' : 'reload', { nodeId: current.id, url });
  return current;
}
```
- **Fixed Code Replacement:**
```js
if (current && current.url === url) {
  if (navigationHint === 'back-forward' || navigationHint === 'manual') {
    current.navigationKind = navigationHint;
    current.confidence = 'low';
  }
  // A 'link' hint means the content script's LINK_CLICK already grew this
  // node and recorded its own 'navigation' event moments ago; stamping
  // 'reload' on top mislabels every ordinary link click as a reload and
  // burns the per-session event cap twice as fast. Genuine reloads carry
  // the 'reload' hint and are still recorded.
  if (navigationHint === 'back-forward') addEvent(session, 'back_forward', { nodeId: current.id, url });
  else if (navigationHint !== 'link') addEvent(session, 'reload', { nodeId: current.id, url });
  return current;
}
```
Trail is now `["mission_started","origin_planted","navigation"]`; real reloads (`transitionType: 'reload'`) and back/forward still record exactly one event each (pinned by A2).

### Issue 4 — HIGH: `search_refinement` event mutated cache then discarded (`NO_CHANGE`)

- **File & Line Area:** `background/service-worker.js` `observeTab()` (~L534–538)
- **Failure Mode:** `addEvent(session, 'search_refinement', …)` mutated the **shared state cache**, then the function returned `NO_CHANGE`, and `runMutatorWithRetry` skips `saveState` for `NO_CHANGE`. Consequences (reproduced): the event appeared in `GET_SNAPSHOT` immediately but not in storage; on service-worker suspension it vanished; or it was later persisted as a side effect of an unrelated mutation with misleading timing. It also violated the queue's core invariant that `NO_CHANGE` means "nothing was touched."
- **Original Code Fragment:**
```js
if (isSearchUrl(url) && !originNotSet) { addEvent(session, 'search_refinement', { url }); return NO_CHANGE; }
```
- **Fixed Code Replacement:**
```js
// Returning NO_CHANGE after addEvent() mutated the shared state cache left
// the event unpersisted (visible to reads, then lost on a worker restart or
// smuggled into a later unrelated write). Return a changed marker so the
// refinement note is durably saved like every other recorded event.
if (isSearchUrl(url) && !originNotSet) { addEvent(session, 'search_refinement', { url }); return { refined: true, nodeId: current?.id || null }; }
```
No branch node is created (behavior preserved); the event now persists immediately and cache/storage agree (pinned by A3).

### Issue 5 — MEDIUM: companion chip/card go stale on idle pages (no cross-context sync)

- **File & Line Area:** `content/content.js` (refresh plumbing ~L537–545; new listener block ~L601–622)
- **Failure Mode:** The content script only refreshed on load, `pageshow`, `visibilitychange`, URL change, or its own button actions. A mission planted from the **popup**, ended from the **New Tab page** or **Alt+F**, paused from another tab, or re-tuned in **Settings** never reached already-open pages: the chip stayed missing or showed the old mission indefinitely. The worker already persists every change to `chrome.storage.local`, and content scripts can subscribe to `chrome.storage.onChanged` — the sync channel was simply never wired.
- **Original Code Fragment:** (absent — no storage listener existed; `refresh()` had no freshness tracking)
```js
const safeRefresh = wrapWithErrorBoundary(refresh, { category: ERROR_CATEGORIES.MESSAGING, function: 'refresh', swallow: true });
async function refresh(observe = true) {
  try {
    if (observe) await send('OBSERVE_PAGE', { url: location.href, title: document.title });
    await safeUpdate(await send('GET_ACTIVE_VIEW'));
  } catch { update(null); }
}
```
- **Fixed Code Replacement:**
```js
// Timestamp of the most recent view refresh; the storage-sync gate below
// uses it to skip redundant refreshes right after a navigation-driven one.
let lastRefreshAt = 0;
const safeRefresh = wrapWithErrorBoundary(refresh, { category: ERROR_CATEGORIES.MESSAGING, function: 'refresh', swallow: true });
async function refresh(observe = true) {
  lastRefreshAt = Date.now();
  try {
    if (observe) await send('OBSERVE_PAGE', { url: location.href, title: document.title });
    await safeUpdate(await send('GET_ACTIVE_VIEW'));
  } catch { update(null); }
}

// ... near the end of initContentScript(), before the bootstrap calls:

// Cross-context sync: a mission can be planted, ended, paused, or re-tuned
// from the popup, the New Tab page, the dashboard, or the Alt+F shortcut
// while this page sits idle. Every such change is persisted to
// chrome.storage.local by the worker, so watching that key keeps the chip
// and choice card truthful without waiting for a navigation. The debounce
// coalesces write bursts, and the freshness gate skips the sync when a
// navigation-driven refresh just ran, keeping this tab well inside the
// worker's message rate limit. The key mirrors STORAGE_KEY in
// shared/state.js; this classic content script cannot import ES modules.
let storageSyncTimer = 0;
const STORAGE_SYNC_KEY = 'focusForestState';
const STORAGE_SYNC_DEBOUNCE_MS = 200;
const STORAGE_SYNC_MIN_GAP_MS = 600;
chrome.storage?.onChanged?.addListener(wrapWithErrorBoundary((changes, area) => {
  if (area !== 'local' || !changes || !Object.hasOwn(changes, STORAGE_SYNC_KEY)) return;
  window.clearTimeout(storageSyncTimer);
  storageSyncTimer = window.setTimeout(() => {
    if (Date.now() - lastRefreshAt < STORAGE_SYNC_MIN_GAP_MS) return;
    safeRefresh(false);
  }, STORAGE_SYNC_DEBOUNCE_MS);
}, { category: ERROR_CATEGORIES.CONTENT_SCRIPT, function: 'storage.onChanged', swallow: true }));

safeLoadSettings();
safeRefresh(true);
safeScheduleWatch();
```
Bounded timers only (the security sentinel forbidding `setInterval` in content stays green), and the freshness gate keeps per-tab message volume inside the worker's 100/min rate limit during active browsing.

```js
 * Registered in manifest.json with "world": "MAIN" (Chrome 111+), this tiny
 * classic script runs in the PAGE's JavaScript world, where it can wrap
 * history.pushState / history.replaceState. The isolated content-script world
 * cannot see page-initiated calls to those methods: assigning to `history.*`
 * there only shadows the method for the isolated world.
 *
 * The bridge carries NO payload. It re-announces each same-document history
 * write as a plain DOM CustomEvent, which crosses into the isolated world;
 * content/content.js listens for it and re-reads `location.href` and
 * `document.title` itself. A page therefore cannot smuggle data into the
 * extension through this channel, and dispatching a synthetic event without an
 * actual URL/title change is a no-op downstream (the isolated side only acts
 * when the URL or title really differs).
 *
 * The service worker independently observes these navigations through
 * chrome.webNavigation.onHistoryStateUpdated; this bridge exists so the
 * on-page companion chip updates immediately instead of waiting for the
 * 2.5 s polling fallback.
 */
(() => {
  'use strict';
  // Namespace matches the listener in content/content.js.
  const BRIDGE_EVENT = 'focus-forest-history';

  function announce() {
    try {
      document.dispatchEvent(new CustomEvent(BRIDGE_EVENT));
    } catch {
      // The document can be gone mid-teardown; the service worker's
      // webNavigation listener still covers the navigation itself.
    }
  }

  const originalPushState = history.pushState.bind(history);
  const originalReplaceState = history.replaceState.bind(history);

  history.pushState = function pushState(...args) {
    const result = originalPushState(...args);
    announce();
    return result;
  };

  history.replaceState = function replaceState(...args) {
    const result = originalReplaceState(...args);
    announce();
    return result;
  };
})();
```

### V2-A (HIGH, introduced by Phase-1 fix 12) — repaired imports accrued phantom focus time
- **Location:** `background/service-worker.js` `getDashboardStats()`
- **Failure Mode:** Fix 12 cleared inverted `endedAt` to `null`; stats computed `sessionEnd = session.endedAt || now`, so a completed session with `null` end accrued time **up to the present on every stats call**. Repro: a 90-day-old inverted import produced `totalFocusTime = 7,776,000 s` and a 90-day row in Recent Sessions — strictly worse than the pre-fix clamped-to-0 behavior. The pre-existing future-skew repair shared the hazard.
- **V2 Fixed Block:**
```js
const sessionStart = session.startedAt || now;
// A completed session with a missing endedAt (an import whose inverted or
// future-skewed timestamp was repaired to null, or a legacy record) must
// NOT accrue elapsed time up to "now" — that fabricates phantom multi-day
// sessions in the totals. Count it as zero-length; only genuinely active
// sessions accrue to the present.
const sessionEnd = session.endedAt || (session.status === 'completed' ? sessionStart : now);
const sessionDuration = Math.max(0, (sessionEnd - sessionStart) / 1000);
// ...and in the Recent Sessions mapping:
const start = session.startedAt || now;
// Same rule as totalFocusTime: a completed session without a usable
// endedAt is zero-length, never "still running since startedAt".
const end = session.endedAt || (session.status === 'completed' ? start : now);
const duration = Math.max(0, (end - start) / 1000);
```
Post-fix repro: `totalFocusTime: 0`, history duration `0`; active sessions still accrue (A11 pins both halves, including the 3599–3601 s live-session bound).

### V2-B (MEDIUM, gap in Phase-1 fix 3) — self-link reloads recorded nothing
- **Location:** `background/service-worker.js` (`trackLink` existing-node branch, `observeTab` same-URL branch, new `selfLinkMarks` map)
- **Failure Mode:** Suppressing `reload` for every `link`-hint observation also silenced the genuine article: a click on a link pointing at the tab's current URL is a real reload, and `trackLink` records no `navigation` event for it (node already existed). Repro confirmed zero events for a self-link reload.
- **V2 Fixed Block:**
```js
const selfLinkMarks = new Map();
const MAX_SELF_LINK_MARKS = 64;

function markSelfLink(tabId, url) {
  if (!Number.isInteger(tabId) || typeof url !== 'string' || !url) return;
  const now = Date.now();
  for (const [key, entry] of selfLinkMarks) {
    if (now - entry.createdAt >= SERVICE_WORKER.SESSION_TIMEOUT_MS) selfLinkMarks.delete(key);
  }
  while (selfLinkMarks.size >= MAX_SELF_LINK_MARKS) {
    selfLinkMarks.delete(selfLinkMarks.keys().next().value);
  }
  selfLinkMarks.set(tabId, { url, createdAt: now });
}

function takeSelfLinkMark(tabId, url) {
  const entry = selfLinkMarks.get(tabId);
  if (!entry) return false;
  selfLinkMarks.delete(tabId);
  return entry.url === url && Date.now() - entry.createdAt < SERVICE_WORKER.SESSION_TIMEOUT_MS;
}

// trackLink, existing-node branch:
if (existing) {
  const nextTitle = compactText(title || destination);
  if (nextTitle && nextTitle !== existing.title) existing.title = nextTitle;
  // A same-tab click on a link that points at the page the tab already
  // shows is a reload-by-link about to commit. No navigation event is
  // recorded here (the node already existed), so leave a short-lived,
  // commit-verified mark for observeTab to turn into a single 'reload'
  // note. New-tab clicks and SPA route changes are not browser reloads
  // and must not be marked.
  if (!targetBlank && navigationKind !== 'spa') markSelfLink(tabId, destination);
  return existing;
}

// observeTab, same-URL branch:
if (navigationHint === 'back-forward') addEvent(session, 'back_forward', { nodeId: current.id, url });
else if (navigationHint === 'link') { if (takeSelfLinkMark(tabId, url)) addEvent(session, 'reload', { nodeId: current.id, url }); }
else addEvent(session, 'reload', { nodeId: current.id, url });
```
Design notes: commit-verified (marked at click, recorded only after the navigation actually commits — a page that `preventDefault`s the click records nothing); single-use + URL-exact + 15 s TTL + 64-entry FIFO cap; cleared in `clearRuntimeTracking()` (CLEAR_DATA), `tabs.onRemoved`, and Forget Site. A10 pins: self-link → exactly one `reload`; no replay; `target=_blank` self-link → none; ordinary links → still none (A2 unchanged).

## Phase 3 — The real-extension lane (closing the Tier-1 hole)

The QA-director verdict called the extension integration layer Tier 1: zero execution coverage, and the riskiest changes lived there. Phase 3 built that coverage (`test-extension-load.mjs`, 9 gates, wired into CI + `npm run test:extension` / `test:all`) and immediately proved its worth — the first runs surfaced **three real product bugs invisible to every mock**:

### P3-1 (HIGH) — New-tab takeover raced the override and cancelled user navigations
- **Location:** `background/service-worker.js` — `newTabCandidateUrl`, `tabs.onCreated`/`tabs.onUpdated` handlers.
- **Failure Mode:** With our own `chrome_url_overrides` active, a new tab transiently reports the browser placeholder (`pendingUrl`, then loading-phase `tab.url` = `chrome://newtab/`). The takeover issued a redundant `tabs.update` to the same planting page the override was already loading — double-loading every new tab in the product's hottest path, aborting the override's own load (observed: `ERR_ABORTED` on the extension document), and cancelling whatever navigation came next. Proven in vivo: it killed the post-plant search navigation and snapped the tab back.
- **Fix:** One deterministic takeover point — `onUpdated` at `status === 'complete'` with a *committed* browser-NTP URL (override active ⇒ committed URL is our page ⇒ skip; override genuinely off ⇒ placeholder committed ⇒ take over). `onCreated` takeover removed (it can only see uncommitted URLs). Mock fixtures re-pinned to the race-free contract (`loading`-phase placeholders must NOT trigger takeover).

### P3-2 (HIGH) — Every commit is observed twice; twins fabricated events
- **Location:** `background/service-worker.js` — `observeTab` same-URL/replant/known/creation branches; `trackLink`.
- **Failure Mode:** Production observes each navigation twice (new document's `OBSERVE_PAGE` + worker's `tabs.onUpdated`), in either order, with an unbounded gap on slow pages. The navigation hint is consumed by the first observer, so the twin fell through to `addEvent('reload')`: pre-Phase-1 production recorded up to TWO spurious reloads per link click and a `back_forward`+`reload` pair per Back. My Phase-1/V2 single-observation fixes passed mocks and still failed in vivo (`1 !== 0` on the first real-browser run). An intermediate time-window design was tried and rejected (swallows genuine sub-window reloads; fails on slow-page twins).
- **Fix (final):** Timing-independent classification — `trackLink` leaves commit-verified per-tab marks (`new-node` suppresses order-independently; `self-link` restores exactly one genuine reload), and per-tab **commit memos** make the hint-less twin of any classified commit a no-op across every branch (same-URL, replant, known-reuse, refinement, capacity). Fresh hints always classify, so genuine repeated reloads still record. All bounded (FIFO caps) and cleaned on tab close / Forget Site / CLEAR_DATA. Pinned by A2/A10/A14 rewrites (sleep-free — the semantics are timing-independent by construction) and Gate 1 in vivo.

### P3-3 (HIGH) — SPA routes mislabeled as unlinked depth-0 paths
- **Location:** `background/service-worker.js` — `tabs.onUpdated` handler.
- **Failure Mode:** Chromium fires the identical `onUpdated` loading→complete signature for same-document `pushState`/`replaceState` as for real navigations (`changeInfo.url` absent at complete; `onCommitted` never fires). `observeTab` raced — and usually beat — `onHistoryStateUpdated`/`SPA_NAVIGATION`, recording every SPA route as an external `manual` depth-0 node detached from its parent. Proven in vivo (bridge chain verified working: dispatch → isolated listener → `SPA_NAVIGATION` received; node landed `kind:"manual", depth:0` instead of `kind:"spa", depth:1`). This silently fragmented trees on exactly the apps the store listing promises ("Tracks branch transitions accurately on YouTube, GitHub, Notion").
- **Fix:** `onCommitted` records a per-tab commit record (`committedNavs`); `onUpdated` observes only when a matching record exists (consumed once). Same-document completes are ignored — the SPA paths own them. Content-script `OBSERVE_PAGE` still covers full navigations even if a worker restart loses the record. Pinned by A15 + Gate 2 in vivo (including hostile synthetic bridge events creating nothing).

### P3-4 (MEDIUM) — Rate limiter clipped the hero use case (Gate 5, predicted → proven → fixed)
- **Failure Mode:** ~3 companion messages per tracked navigation ⇒ the 100/min per-tab budget capped out at ~34 navigations/min — a fast research session (the product's own store-listing scenario) lost tracking and hid the chip mid-mission, because a rate-limited `null` was indistinguishable from "no session".
- **Fix:** Budget 300/min (`RATE_LIMIT_MAX_REQUESTS`, comment-documented); first-party extension-page senders exempt (`isExtensionPageSender` before limiting); limited content senders receive `{ rateLimited: true }` and the companion keeps its last known view (`update()` early-return, `loadSettings` guard); `pageshow` refresh only on bfcache restores. Pinned by A13 (exact-budget + exemption contract), the updated pinned test in `test-service-worker.mjs`, and Gate 5 in vivo: **40 navigations in ~7.5 s (≈320/min) → 40/40 tracked, chip alive**, stable across 4 consecutive suite runs.

### Harness engineering notes (recorded so nobody relitigates them)
The suite's header documents the Chromium/new-headless quirks that shaped it, each established by controlled experiments (dbg traces kept out of the repo):
- Playwright `goto('chrome://newtab')` (WebUI-mapped) poisons the tab's next routed cross-origin commit — the override is verified via a real browser-opened tab (`chrome.tabs.create`) instead.
- Routed browser-initiated cross-origin commits (fulfilled doc, 302, abort, 204 — all four variants) sporadically abort or poison the tab's next navigation; the engine-navigation contract therefore stays in unit tests (exact `search.query`/`tabs.update` URLs), while E2E lands the SERP via same-class navigations.
- ext→http crossings abort on tabs that have round-tripped; the suite keeps pages in fixed origin roles (extension-origin sender, http-native tracked tab) with zero page churn.
- Closed shadow DOM is asserted via CDP `DOM.getDocument {pierce:true}` + `DOM.getBoxModel` + trusted `Input.dispatchMouseEvent` (which also proves the `event.isTrusted` gate accepts real clicks).
