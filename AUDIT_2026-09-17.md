Date: 2026-09-17

## Scope and confidence

This is an interim review, NOT the exhaustive every-file/every-function audit requested. Some earlier reads were truncated. UI source, styles, remaining scripts, historical reports, assets and lifecycle behavior still require systematic inspection. ## Product assessment

Focus Forest 0.3.4 is a local-first Manifest V3 Chromium browsing companion. A mission supplies an intention; navigation relationships form a tree; increasing branch depth invites reflection rather than blocking websites. A garden preserves sessions and compost preserves pages for later. New Tab, popup, settings and dashboard are separate extension pages. The service worker coordinates state and browser events. There are no declared runtime dependencies; Playwright is development-only.

The strongest idea is the combination of intention, explainable navigation history, gentle intervention and permission to keep exploring. Depth measures structural distance, NOT relevance, distraction or productivity. Copy and analytics should preserve that distinction.

This is a promising, coherent prototype. Bounded storage, dependency-light implementation and a non-punitive tone are good foundations. Data correctness, deletion semantics and browser lifecycle reliability should precede additional visual or reward features.

### Is it unique?

Not in individual ingredients: tree-based browsing history, focus companions, save-for-later lists and nature-themed motivation are established categories. The README acknowledges related navigation-tree projects. The combination may be distinctive, but source inspection cannot establish market-wide novelty. Avoid claiming "the first" without a current product comparison. Validate differentiation with users: do they understand why a prompt appeared, feel respected, and return to their own intentions?

## Findings

### Fixed: incorrect calendar duration

C:\Users\USER\Desktop\Focus-Forest-main\Focus-Forest\background\service-worker.js:554 and :728 defined a day as a maintenance minute multiplied by 24: 24 minutes, not 24 hours. Weekly dates collapsed, streaks counted repeated dates, and the supposed five-year import window was about 30.4 days. Added DAY_MS = 86400000 to C:\Users\USER\Desktop\Focus-Forest-main\Focus-Forest\shared\constants.js and used it at both sites. Historical damage from past imports is not automatically repaired.

### Fixed after regression: Forget Site skipped storage when only saved items matched

C:\Users\USER\Desktop\Focus-Forest-main\Focus-Forest\background\service-worker.js:937-948 filtered nodes and compost but returned NO_CHANGE when zero nodes were removed, so a compost-only deletion changed memory without persisting; saved items reappeared after a worker restart. A stored-storage regression in C:\Users\USER\Desktop\Focus-Forest-main\Focus-Forest\test-service-worker.mjs failed on the original code (forget_saved survived), then passed after counting compost removals toward the changed result. A no-match request still returns null.

Still open on this path: origin metadata and event URLs are not removed, node removal can orphan child relationships, and results are asserted against the mutable cache plus mocked storage rather than a freshly reloaded real storage backend.

### Unresolved: import data integrity — medium priority

C:\Users\USER\Desktop\Focus-Forest-main\Focus-Forest\background\service-worker.js:759-777 concatenates sessions without ID deduplication, omits rewardHistory, and computes the merge before queueing replacement. Repeated imports can duplicate sessions; rewards disappear from replacement state; concurrent updates may be overwritten. Move read/merge/write into the mutation queue and specify conflict policies. These paths were inspected; no new behavioral tests cover these findings yet.

### Unresolved: compaction policy — medium priority

C:\Users\USER\Desktop\Focus-Forest-main\Focus-Forest\shared\state.js:381-396 retains the last 20 compost items, although additions go at the beginning elsewhere. This retains older saves. It returns false for compost-only changes because the return value counts removed sessions. Specify retention order and return whether any persistent change occurred.

### Security/privacy hardening — not confirmed external exploits

- No storage.setAccessLevel call was found in the searched runtime directories. Restrict history storage to TRUSTED_CONTEXTS after checking callers. Compact message responses do not themselves restrict the extension's own content-script storage API access. Ordinary websites do not thereby gain direct storage access.
- C:\Users\USER\Desktop\Focus-Forest-main\Focus-Forest\shared\error-tracing.js logs context and stacks; import warnings can include URLs. Redact sensitive components and bound diagnostic strings before retention and logging.
- Import traverses input before output limits apply. Bound input bytes and collections before expensive processing. Bounded stored output does not imply bounded processing work.
- Broad host permissions fit passive tracking but enlarge exposure. Explain permissions clearly and evaluate optional access without silently breaking workflows.
- The development preview binds to all interfaces. Prefer loopback by default. Its asset allowlist is a positive control; network reachability alone is not a file-read vulnerability.

Positive controls observed: no web-accessible resources, restrictive script/connect CSP, URL normalization, privileged-operation sender checks, and sender-boundary tests. Static regex contracts are guardrails, not a security certification.

## Performance optimization plan

1. Establish baselines in an installed extension: idle worker wakeups, storage writes/bytes per navigation, message latency, dashboard render time, DOM count, long tasks, heap after repeated route changes. Mocked UI tests cannot measure full lifecycle behavior; browser tests were blocked by missing Playwright in this environment.
2. Bound work before normalization. Slice or reject oversized import collections before mapping; reject invalid timestamp ranges early; cap the day-splitting loop to relevant dates while keeping correct UTC day semantics.
3. Bound runtime maps. messageCounts and navigationHints lack tab-removal cleanup and enforced maxima despite declared constants. Sample repeated rate-limit warnings instead of building a stack trace and formatted log per rejected message.
4. After profiling, replace avoidable copies such as the reversed-array lookup in nodeForTab with an indexed reverse loop. A persistent node index adds invalidation complexity; measure first.
5. Keep one serialized writer. Measure full-state serialization and broadcast cost; coalesce redundant observations only if durability on worker suspension is preserved. Avoid long debounced writes.
6. Profile rendering before adding pooling, virtualization, or frameworks. Coalesce updates per frame, render visible panels only, reuse deterministic layout when topology is unchanged, and re-verify keyboard selection and reduced motion.

Acceptance criteria: correctness suite unchanged or strengthened; no unbounded retained-map growth across tab open/close cycles; no dropped distinct SPA routes; no history loss after worker restart. Set latency/heap budgets from measured baselines.

## Refactoring plan

Small, independently tested changes; keep native ES modules and Node's built-in test tools; no runtime dependencies.

1. Consolidate constants by meaning. C:\Users\USER\Desktop\Focus-Forest-main\Focus-Forest\shared\constants.js declares storage keys and validation limits that differ from the active definitions in C:\Users\USER\Desktop\Focus-Forest-main\Focus-Forest\shared\state.js. Enumerate consumers, delete unused definitions, and separate calendar durations from operational intervals (the DAY_MS fix is step one).
2. Extract pure calendar/statistics calculations from C:\Users\USER\Desktop\Focus-Forest-main\Focus-Forest\background\service-worker.js behind an injected clock; keep browser message handling as a thin adapter.
3. Split normalization, URL policy, rewards, and persistence in C:\Users\USER\Desktop\Focus-Forest-main\Focus-Forest\shared\state.js; expand dense one-line functions like compactSession into named operations without changing the schema.
4. Route import, compaction, deletion, and navigation mutations through one transaction interface with explicit no-change semantics; never mutate the shared cache without persistence (the Forget Site fix illustrates the failure mode).
5. Separate worker navigation-relationship logic from message authorization/schema checks and event registration; test allowed and denied senders behaviorally.
6. After reading all UI callers, share messaging/recovery utilities only where contracts genuinely match; do not unify unrelated page lifecycles for line count.
7. Consolidate overlapping historical audit documents into one current issue ledger with status, evidence, and verification date; keep historical reports as history.

## Product improvement suggestions

- Explain why each branch relationship was inferred and let users correct misattribution.
- Frame deep exploration neutrally ("deep branch"), never as failure; allow explicitly marking intentional deep research.
- Distinguish elapsed session time from active browsing time across idle gaps and multiple windows.
- Make retention caps visible before they bite (12 sessions, 96 nodes, 72 events, 80 compost items) and explain what is retained, with working export.
- Finish privacy deletion semantics before adding more stored metadata; make pause and exclusion controls obvious.
- Test keyboard-only use, focus restoration, contrast, zoom, reduced motion, and screen readers on real pages.
- Keep rewards optional and subordinate to reflection; avoid streak pressure.
